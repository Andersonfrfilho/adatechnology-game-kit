# T0.2 🧠 — Contrato da bancada (desenho validado por architect/opus, 2026-10-23)

Camada opcional **bench** no contrato genérico de módulo: o módulo declara controles, camadas e contadores como dados; a sala guarda os
valores, desenha tudo de forma genérica, persiste na URL (pela página de exemplo) e devolve as mudanças ao módulo por um único
`ModuleHost.bench` opcional. Os eventos de arma que faltavam viram **tipos genéricos de `HostEvent`** (`mode`, `fault`, `clear`, `safety`
e `rounds`/`mode` opcionais em `shot`), porque a fonte é a regra da ferramenta do host (A5), não o módulo. Tudo opcional: módulos atuais
continuam compilando.

## 1. `game-contracts/src/bench.ts` (novo)

```ts
import type { Vec3 } from './destruction'

export type ControlValue = number | boolean | string
export interface ChoiceOption { readonly id: string; readonly name: string }
interface ControlBase { readonly id: string; readonly name: string; readonly hint?: string; readonly hidden?: boolean }
export interface NumberControl extends ControlBase { readonly kind: 'number'; readonly min: number; readonly max: number; readonly step?: number; readonly unit?: string; readonly default: number }
export interface BooleanControl extends ControlBase { readonly kind: 'boolean'; readonly default: boolean }
export interface ChoiceControl extends ControlBase { readonly kind: 'choice'; readonly options: readonly ChoiceOption[]; readonly default: string }
export interface ActionControl extends ControlBase { readonly kind: 'action' }
export type ModuleControl = NumberControl | BooleanControl | ChoiceControl | ActionControl
export interface ModuleLayer { readonly id: string; readonly name: string; readonly default?: boolean }
/** Pulled: the room calls read only when it samples (~4 Hz, or on TestRoom.metrics()). */
export interface ModuleMetric { readonly id: string; readonly name: string; readonly unit?: string; readonly max?: number; readonly digits?: number; read(): number | string }
export type BenchChange =
  | { readonly kind: 'control'; readonly id: string; readonly value: ControlValue }
  | { readonly kind: 'layer'; readonly id: string; readonly on: boolean }
  | { readonly kind: 'action'; readonly id: string }
export interface ControlPatch { readonly hidden?: boolean; readonly disabled?: boolean; readonly options?: readonly ChoiceOption[]; readonly value?: ControlValue }
export interface ModuleBench {
  value(id: string): ControlValue | undefined
  layer(id: string): boolean
  /** Right after attach returns, the host sends one change per control (not actions) and per layer, in declaration order. */
  onChange(listener: (change: BenchChange) => void): () => void
  /** `value` sets without emitting (no echo loops); `options` falls back to the first option if the value is no longer offered. */
  patch(id: string, patch: ControlPatch): void
  look(eye: Vec3, target: Vec3): void
}
export interface BenchReport { readonly ok: boolean; readonly problems: readonly string[] }
/** snake_case ids unique across controls, layers and metrics; min < max; step > 0; default in range; options non-empty, unique, default among them; metric max > 0. */
export function checkBench(declared: { readonly controls?: readonly ModuleControl[]; readonly layers?: readonly ModuleLayer[]; readonly metrics?: readonly ModuleMetric[] }): BenchReport
```

## 2. `game-contracts/src/module.ts`

```ts
export type HostEvent =
  | { type: 'tool'; weapon: string }
  | { type: 'shot'; weapon: string; shots: number; recoil: [number, number]; rounds?: number; mode?: string } // rounds = cartuchos; shots = projéteis
  | { type: 'reload'; weapon: string; phase: 'start' | 'end' }
  | { type: 'empty'; weapon: string }
  | { type: 'mode'; weapon: string; mode: string }
  | { type: 'fault'; weapon: string; fault: string }
  | { type: 'clear'; weapon: string; fault: string; phase: 'start' | 'end' }
  | { type: 'safety'; weapon: string; on: boolean }

HostTool += mode?: string; fault?: string; safety?: boolean; heat?: number /* 0..1 */
ModuleHost += bench?: ModuleBench
TestableModule += controls?(locale): ModuleControl[]; layers?(locale): ModuleLayer[]; metrics?(locale): ModuleMetric[]
```

Manter `interface` como no arquivo; `readonly` só nos tipos novos. Exportar tudo e `checkBench` no `index.ts`.
Nomes de ciclo de ferramenta (`mode`, `fault`, `clear`, `safety`), nunca "jam"/"burst": servem a pistola de prego, motosserra, mangueira
(teste do GTA).

## 3. `game-test-room`

- `src/bench.ts` (puro): `createBenchStore(module, locale)` com declarações, patches, valores e camadas; `set` limita a [min,max] e encaixa
  no `step`, recusa id desconhecido, tipo errado e opção não oferecida. `encodeBenchState` / `decodeBenchState`: `id=valor;id=valor` com
  `encodeURIComponent`, booleanos e camadas como `1`/`0`; o decode trata a entrada como **hostil** (descarta id desconhecido, NaN, opção
  não oferecida, par malformado; limita números).
- `src/metrics.ts`: fps e ms por quadro por janela de 0,5 s de `dt` real **antes** do `timeScale` (câmera lenta não muda). `draw_calls` e
  `triangles`: copiar `gl.info.render.calls/.triangles` logo após `gl.render` quando a sala é dona do laço; senão ler `gl.info?.render` na
  amostragem; sem `info` → `undefined`. `objects/fragments/particles/decals` de `renderer.stats()` + `fluidView.stats()` só na amostragem.
  Amostragem a 4 Hz no tick do HUD (`hudAcc`), só com UI ligada e painel visível; `read()` dos módulos no mesmo ritmo. Custo por quadro:
  um incremento, uma soma, duas cópias.
- `room.ts` só liga:
  1. `detachers` vira `Map<moduleId, () => void>`; `loadModule` chama o detacher antigo antes de anexar de novo (corrige o bug de anexar
     duas vezes, contrário ao que `TestRoom.loadModule` promete).
  2. `checkBench` no `loadModule` → linhas `mod.bench_ok` / `mod.bench_fail`, `report.ok`.
  3. Um `ModuleHost` **por módulo** (membros comuns + `bench` ligado à store do módulo), só se o módulo declarar algo; `look` → `room.look`.
  4. Depois do `attach`, enviar as mudanças iniciais.
  5. Módulo ativo: `openArea(group)` quando o grupo/id é de um módulo; senão o último carregado com bancada. O painel mostra só o ativo.
  6. Emitir `{ type: 'mode' }` no `KeyQ`.
  7. `rounds` e `mode` no evento `shot` (`rounds = shots.filter(s => s.pellet === 0).length`).
  8. `fault`, `clear`, `safety` e suas teclas ficam para a Fase 1 (T1.3), quando o `WeaponState` expuser pane e trava.
- `types.ts`:
  ```ts
  TestRoomOptions += metrics?: readonly RoomMetricId[] | false; bench?: { readonly state?: string; readonly onChange?: (moduleId: string, encoded: string) => void }
  TestRoom += bench(moduleId?: string): BenchHandle | null; metrics(): { room: Partial<Record<RoomMetricId, number>>; module: Record<string, number | string> }
  export type RoomMetricId = 'fps' | 'frame_ms' | 'draw_calls' | 'triangles' | 'objects' | 'fragments' | 'particles' | 'decals'
  export interface BenchHandle { controls(); layers(); value(id); layer(id); set(id, value): boolean; setLayer(id, on): boolean; act(id): boolean; encode(): string }
  ```
- UI em `src/bench-panel.ts` (novo): painel `tr-panel tr-bench` na coluna direita entre `anim` e `tests`; número → range + leitura com
  unidade; booleano → checkbox; escolha → botões segmentados com `aria-pressed` (≤4) ou `<select>`; ação → `tr-btn`; camadas → lista
  "Camadas"; contadores → `<dl>` atualizando só o texto a 4 Hz, com `tr-bar` (`warn` ≥80%, `bad` >100%) quando há `max`. Linha compacta
  com os contadores da sala no topo. `UiOptions` += `onControl`, `onLayer`, `onAction`; `RoomUi` += `bench(view | null)`, `metrics(rows)`.
  Textos em `locale.ts` (en e pt-BR): `ui.bench`, `ui.layers`, `ui.metrics`, `metric.<id>`, `mod.bench_ok`, `mod.bench_fail`.
- URL: a sala nunca toca em `location`; `examples/test-room/src/main.js` passa `bench: { state: params.get('bench'), onChange }` e faz
  `history.replaceState` com `?bench=`.

## 4. Adoção em `game-weapons-three` (só esboço; Fase 1, T1.3/T1.6)

`attach` trata `mode`, `shot.rounds` (ejetar `rounds` estojos na cadência), `fault` (estojo preso, como `stuckCase` da Galeria), `clear`
(movimento e som do `clearJam`), `safety` (alavanca). Camadas `casings`, `magazines`, `muzzle_flash`; contadores `casings_live`,
`magazines_live`, `heat` (max 100). Atirar, rajada e destravar são entrada do jogador na regra do host, não botões do módulo.
Qualidade da munição é opção da regra (T1.1), não controle da bancada.

## 5. Testes (vitest)

- `game-contracts/tests/bench.test.ts`: declaração válida passa; cada erro (id duplicado entre controle/camada/contador, id fora de
  snake_case, min ≥ max, step ≤ 0, default fora, opções vazias, default fora das opções, max ≤ 0) falha com problema nomeado; módulo sem
  os membros novos continua satisfazendo `TestableModule`.
- `game-test-room/tests/bench.test.ts`: mudanças iniciais em ordem; `set` limita/encaixa, id/tipo errado → false sem emitir; `act`;
  `setLayer`; `patch({value})` não emite; `patch({options})` cai na primeira; encode/decode ida e volta; entrada hostil
  (`size=NaN;x=1;fx=%ZZ;mode=nope`) descartada/limitada; `options.bench.state` restaurado **antes** das mudanças iniciais; declaração ruim →
  `report.ok === false` e linha `check/fail`; carregar duas vezes → attach 2×, detach 1×, um evento chega uma vez só.
- `game-test-room/tests/metrics.test.ts`: 60× `update(1/60)` → fps ≈ 60, igual em câmera lenta; stub com `info.render` → `draw_calls` 12;
  sem `info` → `undefined` sem erro; `read` de módulo com zero chamadas em 120 updates sem UI e uma por `metrics()`; `metrics: ['fps']`.
- `module-host.test.ts`: `KeyQ` emite `mode`; rajada → `rounds 3`; escopeta → `shots > 1, rounds 1`.
- UI (happy-dom): painel desenha range/checkbox/botões/select/ação; checkbox de camada emite; texto de contador atualiza após 0,25 s; sem
  linhas de módulo quando ele não declara nada.
- `game-weapons-three`: o módulo continua carregando e aceita `mode`/`fault`/`clear`/`safety` sem erro.

## Riscos

- Com renderizador externo de várias passadas, `info.render` reflete só a última (draw calls subcontados).
- `room.ts` continua grande; a lógica nova mora em arquivos novos, só ~60 linhas de ligação lá.
